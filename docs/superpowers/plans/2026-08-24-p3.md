# P3 实施计划（表单子体系 + 高级组件交互精修）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把已有 `AstForm` 做成对齐 Element UI 的连贯表单（P3-A），并对 7 个进阶组件做一致性审计与精修（P3-B），全部沿用批次 2 纪律。

**Architecture:** P3-A 先定义 `FormValueProvider`(取值) + `FormInvalidMarker`(错误态) 两个轻接口，让自绘字段组件实现，统一被 `AstForm` 消费；P3-B 对每个组件套用「尺寸档位」共享配方并补回归断言。P3-A 先于 P3-B，B 直接复用 A 的取值契约。

**Tech Stack:** Java 8（`javac --release 8`）、纯 javac 构建、零外部依赖；动画沿用 `Animator`/`Easing`/`ElementTheme`；自检用 `java -ea`。

**Spec:** `docs/superpowers/specs/2026-08-24-p3-design.md`

## Global Constraints

- JDK 8，`javac --release 8`（回退 `-source 8 -target 8`），纯 javac 构建，零外部依赖。
- 所有 UI 变化沿用动画引擎（`Animator`/`Easing`/`ElementTheme`）。
- 消灭坐标命中：可清空一律用 `AstCloseButton` 配方（`clearVis` 淡入 + alpha 联动可交互），不得用 `getX() > getWidth()` 之类坐标判断。
- 文本对比度 ≥ 4.5:1（AA）、大文本/图标 ≥ 3:1；关键色用 `ElementTheme.assertContrast(...)` 在 self-check 中断言。
- 尺寸档位常量命名：`SIZE_LARGE=0 / SIZE_DEFAULT=1 / SIZE_SMALL=2`（与 `AstInput` 一致）。
- 每个组件 self-check 经 `build.bat` 注册，`java -ea` 全量回归全绿。
- 提交信息前缀：`feat(<组件>):` / `fix(<组件>):` / `refactor(<组件>):` / `docs:`；每子任务一提交。

## 共享配方（Shared Recipes）

### R1：尺寸档位配方（applySizeTier）

每个需补档位的组件，在类内加入：

```java
public static final int SIZE_LARGE = 0, SIZE_DEFAULT = 1, SIZE_SMALL = 2;
private static final int[] TIER_HEIGHT = {40, 32, 28};   // LARGE/DEFAULT/SMALL
private static final float[] TIER_FONT  = {14f, 13f, 12f};
private int tier = SIZE_DEFAULT;

public void setSize(int t) {
    if (t < SIZE_LARGE || t > SIZE_SMALL) throw new IllegalArgumentException("tier");
    this.tier = t;
    applyTier();
    revalidate(); repaint();
}
private void applyTier() {
    setFont(ElementTheme.FONT.deriveFont(TIER_FONT[tier]));
    // 内边距/图标尺寸等随 tier 联动（复制自 AstInput.applyTier 的字段调整）
}
@Override public Dimension getPreferredSize() {
    Dimension d = super.getPreferredSize();
    return new Dimension(d.width, TIER_HEIGHT[tier]);
}
```

每个组件按自身高度语义填 `TIER_HEIGHT`（纯高度组件用 40/32/28；内容驱动组件如 Table/Tree/Transfer 用档位调字体与行高，不在 getPreferredSize 强制高度）。

### R2：CloseButton 清空配方（替代坐标命中）

```java
private String extractValue(JComponent input) {
    if (input instanceof FormValueProvider) return ((FormValueProvider) input).getFormValue();
    if (input instanceof JTextField) return ((JTextField) input).getText();
    if (input instanceof JTextArea) return ((JTextArea) input).getText();
    if (input instanceof JComboBox) { Object s = ((JComboBox<?>) input).getSelectedItem(); return s == null ? "" : s.toString(); }
    return "";
}
```

- [ ] **Step 1.5: 新增 TypeRule（number/date）**

在 `AstForm` 内加：
```java
public static class TypeRule implements ValidationRule {
    public enum Kind { NUMBER, DATE }
    private final Kind kind;
    public TypeRule(Kind k) { this.kind = k; }
    public String validate(String value, String label) {
        if (value == null || value.trim().isEmpty()) return null; // 交给 RequiredRule
        if (kind == Kind.NUMBER) {
            try { Double.parseDouble(value); return null; }
            catch (NumberFormatException e) { return label + "必须是数字"; }
        }
        try { java.time.LocalDate.parse(value, java.time.format.DateTimeFormatter.ISO_LOCAL_DATE); return null; }
        catch (Exception e) { return label + "日期格式应为 yyyy-MM-dd"; }
    }
}
```
`AstForm.selfCheck()` 加断言：
```java
AstForm.TypeRule tn = new AstForm.TypeRule(AstForm.TypeRule.Kind.NUMBER);
assert tn.validate("12.5","x") == null : "type number ok";
assert tn.validate("abc","x") != null : "type number fail";
AstForm.TypeRule td = new AstForm.TypeRule(AstForm.TypeRule.Kind.DATE);
assert td.validate("2026-08-24","x") == null : "type date ok";
assert td.validate("2026/08/24","x") != null : "type date fail";
```

- [ ] **Step 2: 标签定位 + 必填标记**

在 `AstForm` 加字段 `private int labelPosition = POS_LEFT; private int labelWidth = 100; public static final int POS_LEFT=0, POS_TOP=1, POS_RIGHT=2;` 及 `setLabelPosition/setLabelWidth`。`FormField` 构造器接收 `boolean required`（规则含 `RequiredRule`）与 form 的 `labelPosition/labelWidth`，按位置布局（GridBagLayout）：
  - LEFT：标签列（右对齐，`labelWidth` 宽）+ 控件列（填充），错误行置于控件下方整行。
  - TOP：标签行（左对齐，整行）在上，控件行在下，错误行最下。
  - RIGHT：控件列 + 标签列（左对齐）。
  - 必填：`required` 时标签文本前缀红色 `*`（`ElementTheme.DANGER`，`assertContrast` 断言）。

- [ ] **Step 3: 错误态接入 FormInvalidMarker**

`FormField.showError` 增加 `if (input instanceof FormInvalidMarker) ((FormInvalidMarker) input).setInvalid(true);`，并在 `showError` 触发一个轻微 shake：`Animator` 200ms 驱动控件 `xOffset` 在 [-3,3,-2,2,0] 间往返（对齐 Element「校验错误抖动」），`paint`/`revalidate` 时应用 `xOffset`。
`FormField.clearError` 增加 `if (input instanceof FormInvalidMarker) ((FormInvalidMarker) input).setInvalid(false);`
（保留 JTextField 红边框分支）

- [ ] **Step 4: reset()**

`addField` 时记录 `field.initialValue = extractValue(input)`；新增 `public void reset()`：
```java
public void reset() {
    clearAllErrors();
    for (FormField f : fields) {
        if (f.input instanceof FormValueProvider) ((FormValueProvider) f.input).setFormValue(f.initialValue);
        else if (f.input instanceof JTextField) ((JTextField) f.input).setText(f.initialValue);
        // Ast* 组件已实现 FormValueProvider，走上分支
    }
}
```
