## P3-A 表单子体系（核心对齐 Element）

### A.1 字段取值契约（关键设计决策）

新增接口（放 `ui` 包）：

```java
package org.swelement.ui;
public interface FormValueProvider {
    String getFormValue();
}
```

让以下自绘组件实现它（`AstForm.extractValue` 优先 `instanceof FormValueProvider`，回退 `JTextField/JTextArea` 以兼容原生组件）：

| 组件 | `getFormValue()` 实现 |
|---|---|
| `AstInput` | 明文文本；密码模式走 `getPassword()` 拼接为字符串 |
| `AstSelect` | 单选：`selectedValue`；多选：逗号拼接的 `value` 列表 |
| `AstDatePicker` | `"yyyy-MM-dd"` 或空串 |
| `AstInputNumber` | 数值字符串（空则返回 `""`） |
| `AstCascader` | 选中路径拼接（如 `a / b / c`） |

理由：与批次 2 推广 `AstCloseButton` 同一思路——接口内聚、零额外注册、后续新组件顺手实现即可。

### A.2 标签与布局

- `setLabelPosition(POS_LEFT / POS_TOP / POS_RIGHT)`，默认 `POS_LEFT`（对齐 Element 默认）。
- `setLabelWidth(int)`：控制 LEFT/RIGHT 布局下标签列宽（默认 80）。
- 必填标记：当该字段规则含 `RequiredRule` 时，标签前渲染红色 `*`（`ElementTheme` DANGER `#F56C6C`，与白底 ≥4.5:1）。
- `FormItem` 内部用 `GridBagLayout` 排布：标签列 + 控件列 + 错误行（控件下方，TOP 布局时占整行）。

### A.3 校验 UI 与动画

- 错误呈现：控件下方/右侧行内红字 `#F56C6C`（WCAG AA）。
- 出现动画：错误文字 `alpha 0→1` 淡入 + 控件轻微 shake（`Animator` + `Easing`，~200ms），对齐 Element「校验错误抖动」。
- 状态清理：`clearAllErrors()` 清除全部错误与红字；`reset()` 在清错误基础上恢复字段初始值（实现为记录初始 `getFormValue()`，reset 时写回）。

### A.4 规则扩展

保留现有：`RequiredRule` / `MinLengthRule` / `MaxLengthRule` / `RegexRule` / `EmailRule` / `PhoneRule`。
新增：`TypeRule`（枚举 `NUMBER` / `DATE`），做格式校验（呼应字段组件，DATE 用 `yyyy-MM-dd` 正则）。
**明确不做**：异步校验、跨字段联动规则、inline 行内布局变体（YAGNI，留待后续阶段）。

### A.5 Demo

`AstFormDemo`（main 起 JFrame）：登录/注册风格表单，含 `AstInput`（用户名/邮箱）、`AstSelect`（角色）、`AstDatePicker`（生日）、`AstInputNumber`（年龄），演示 required / email / type 校验、行内错误动画、reset 按钮。

### A.6 自检

`AstForm.selfCheck()` 加入 `build.bat`：
- `RequiredRule` 空值 → 返回错误；非空 → null。
- `EmailRule` 合法/非法样本。
- `TypeRule.NUMBER` / `TypeRule.DATE` 合法/非法样本。
- `extractValue` 对 `AstInput` / `AstSelect`（单选+多选）取值正确（用真实组件实例断言，不依赖 Swing 事件派发）。

### A.7 涉及文件

- 新增：`ui/FormValueProvider.java`、`demo/AstFormDemo.java`
- 修改：`ui/AstForm.java`（标签布局、动画、reset、extractValue 扩展）、`ui/AstInput.java`、`ui/AstSelect.java`、`ui/AstDatePicker.java`、`ui/AstInputNumber.java`、`ui/AstCascader.java`（实现 `FormValueProvider`）
- 修改：`build.bat`（注册 `AstForm` 自检）

## P3-B 高级组件交互精修（审计驱动）

### B.1 审计清单（每个组件逐项核）

对下列 7 个组件，逐项审计并补齐缺口：

1. **残留坐标命中**：grep `getX() > getWidth()` / 手绘 `×` / 直接 `mousePressed` 命中计算 → 改用 `AstCloseButton` 配方（淡入 `clearVis`、alpha 联动可交互、无坐标判断）。
2. **尺寸档位**：`setSize(SIZE_LARGE / SIZE_DEFAULT / SIZE_SMALL)` 是否齐备，高度/字体/内边距是否联动（对齐 Input 档位表）。
3. **WCAG 自检**：是否已在 `build.bat` 注册 `java -ea` 自检；对比度关键色（文本/图标/状态）是否 ≥ AA（4.5:1 文本、3:1 大文本/图标）。
4. **Demo 完备**：是否已有可启动 demo 覆盖主要交互；缺则补。

### B.2 组件范围

`AstTable` / `AstDatePicker` / `AstCascader` / `AstTree` / `AstTransfer` / `AstInputNumber` / `AstSelect`(多选部分)。

### B.3 每组件修复模式（TDD）

1. 先扩 `build.bat` 自检或组件内 `selfCheck` 断言（RED：暴露缺口）。
2. 实现修复（GREEN）。
3. 单组件一提交，提交信息 `fix/feat(<组件>): ...`。

### B.4 涉及文件

- 修改：上述 7 个 `ui/*.java`（按审计缺口）。
- 修改：`build.bat`（补齐缺失自检）。
- 可能新增/完善：`demo/` 下对应 Demo。
